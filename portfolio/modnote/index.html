ModNote

Executive summary

University students frequently struggle with fragmented study materials, juggling disconnected text documents, course handbooks, assessment criteria, and lecture notes across disparate locations. ModNote was conceived and engineered as an integrated desktop application designed to centralise academic module information and rich lecture notes within a single unified workspace.

Operating as solo designer and engineer, I conducted task-flow analyses to map student study patterns, devised an information architecture that minimised context switching, and built the complete solution in C# using Windows Forms. The system combined an automated data ingestion engine with custom rich-text serialisation and a WCAG-compliant desktop interface.

ModNote delivered an intuitive, zero-latency desktop environment that allowed students to cross-reference assessment timelines and learning objectives alongside their lecture notes, proving how software engineering and user-centred design converge to eliminate cognitive friction in academic workflows.

What this project proves about me: I possess the technical depth to bridge user experience design and software engineering, translating complex user workflows into clean, performant, native desktop applications from scratch.

The challenge

Undergraduate academic study requires managing dense streams of interconnected information: syllabus objectives, assignment deadlines, recommended reading, and continuous lecture notes. Typically, students distribute this information across disparate Word files, local folders, and institutional Virtual Learning Environments (VLEs).

This fragmentation introduces severe cognitive friction:

  • High context-switching overhead: Students constantly toggle between their note editor and course syllabus documents to verify whether their notes satisfy assignment criteria and module learning outcomes.
  • Unstructured local organisation: File-system folder hierarchies lack relational context, leading to misplaced files and disjointed revision workflows before examinations.
  • Interface bloat in legacy tools: Heavyweight office suites present cluttered toolbars and high memory footprints, distracting students from focused writing and rapid review.

Operating within the technical constraints of the native Windows desktop environment (.NET Framework and Windows Forms), the objective was to design and engineer a responsive, self-contained Create, Read, Update, Delete (CRUD) application tailored specifically to academic workflows.

My process

  1. Workflow mapping & requirements definition: Audited typical student study routines during lectures and revision cycles to isolate key data relationships between modules, assignments, and notes.
  2. Information architecture & interaction wireframing: Mapped a shortest-path navigation model to keep core learning objectives and active note taking visible in a unified viewport.
  3. Visual hierarchy & accessibility design: Established typographic scales, form layouts, and high-contrast palettes evaluated against Web Content Accessibility Guidelines (WCAG) luminosity ratios.
  4. System architecture & OOP engineering: Modelled core entities in C# using encapsulation and inheritance, implementing generic data collections and stream I/O pipelines.
  5. Interface implementation & performance optimisation: Built responsive Windows Forms layout anchors, GDI+ rendering pipelines, and keyboard focus maps for rapid desktop interaction.

What I did

I managed the complete software development lifecycle, transforming initial workflow sketches into an engineered Windows desktop executable.

Desktop interaction & user experience engineering

To eliminate the context switching inherent in standard note taking, I applied a shortest-path architectural model. I analysed academic task flows to ensure that reviewing syllabus requirements while composing lecture notes required zero modal interruptions.

  • Responsive container architecture: Designed custom layout anchors and autoscaling logic within Windows Forms to preserve visual proportions across varying desktop resolutions and DPI display settings.
  • Clear visual hierarchy: Structured forms with generous negative space and clear typographic contrast to avoid the dense, intimidating visual presentation typical of enterprise CRUD software.
  • Accessibility & keyboard acceleration: Implemented a logical tab-indexing sequence and keyboard mnemonic shortcuts throughout the UI, enabling high-speed, mouse-less data entry alongside WCAG-compliant colour contrast.

Laptop mock-up displaying the ModNote module information workspace, presenting a clean split-panel interface for selecting course modules and reviewing their synopsis, learning objectives, and assignment schedules.

Software engineering & system architecture

Behind the graphical interface, I engineered an event-driven C# .NET desktop architecture built for local reliability and speed:

  • Object-Oriented Data Model: Constructed encapsulated classes for Module and Note objects, maintaining relational integrity between academic metadata and user notes.
  • ETL (Extract, Transform, Load) parsing layer: Built automated file-parsing logic to ingest external syllabus files and instantiate structured module objects containing key dates and learning indicators.
  • Rich-text persistence: Implemented a robust serialisation engine handling Rich Text Format (RTF), embedded bitmaps, and URI hyperlinks, backed by stream readers with error-handling boundaries to protect against data corruption.
  • High-throughput retrieval: Utilised generic collections (List<T>, Dictionary<TKey, TValue>) to achieve O(1) and O(n) data retrieval times across local records.

Why I made these decisions

1. Native Windows Forms over a browser or hybrid wrapper

In 2016, building a local utility in Windows Forms rather than an early web-wrapper wrapper (such as early Electron) ensured minimal memory usage, zero install overhead, instant cold-start times, and direct access to native Windows UI event loops. This guaranteed a completely offline-ready tool suitable for lecture halls with intermittent connectivity.

2. Side-by-side split view over tabbed navigation

Rather than forcing users to flip between a 'Syllabus' tab and a 'Notes' tab, I placed module metadata and the active note editor in parallel viewports. Keeping assessment deadlines and learning objectives continuously visible grounds the student's writing directly in the academic requirements of the course.

3. File-stream serialisation over a heavy local database

To maintain portability and keep the software lightweight, I used direct stream I/O and custom object serialisation instead of embedding a heavyweight SQL engine. This allowed students to back up, copy, or move individual course files transparently via standard file explorer utilities.

4. High-contrast typography and comprehensive tab indexing

Academic study frequently involves prolonged hours of screen reading. Prioritising WCAG luminosity ratios and predictable keyboard focus order reduced physical strain and enabled power users to capture thoughts rapidly during fast-paced lectures without reaching for a trackpad.

Impact / results

ModNote successfully solved the user problem of academic fragmentation by combining structured course oversight with responsive note-taking capabilities.
